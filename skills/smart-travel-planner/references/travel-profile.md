# Trip profile
Store destination, start/end/duration, origin, party count/type, total/per-person budget/currency, accommodation and free-stay, transport, pace, walking tolerance, sleep schedule, interests, food, must-visit/avoid, shopping/nightlife, special/visa/language constraints, and weather tolerance. For each value store provenance: user, researched, or assumption; never silently promote an assumption to a fact.

Classify fields as `USER_REQUIRED`, `AGENT_DISCOVERABLE`, `USER_DECISION`, or `UNAVAILABLE`. Include `lodging_area`, `lodging_candidates`, `lodging_recommendation`, `lodging_selection_status`; `airport_candidates`, `flight_candidates`, `flight_recommendation`, `flight_selection_status`; `attraction_candidates`, `attraction_recommendations`; `transit_candidates`, `transit_recommendation`; `restaurant_candidates`, `restaurant_recommendations`; and `decision_status`. Decision status is one of `DISCOVERING`, `PROPOSED`, `USER_DECISION_REQUIRED`, `AUTO_SELECTED`, `CONFIRMED`. Candidate arrays begin empty/`DISCOVERING` and must be populated only by sourced research. A user-selected lodging area is an `AREA_LEVEL_ANCHOR`; property address is optional until final route refinement.
