# Fallback policy
Search unavailable: use available MCP/native tools and label gaps. Maps/routing unavailable: give geographically grouped itinerary but mark durations as estimates. Forecast unavailable or too early: use seasonal/historical climate and say recheck near departure. Exchange unavailable: show native currency and date the conversion assumption or omit conversion. Image unavailable: omit image. DOCX unavailable: deliver structured Markdown/JSON. MCP unavailable: use agent tools and local deterministic scripts. Never fabricate precision to hide a gap.

The MCP `search_web` is selected through a provider abstraction. Native agent search is preferred and must be called by the Skill/host; the local stdio server cannot invoke its host. Wikipedia is a degraded encyclopedia fallback only and cannot promise domain or recency filtering. Transit fallback returns a host-search instruction for official operators; keep time/fare unknown until verified against the itinerary date, route, and first/last service. Never convert a transit fallback into a fabricated duration.
